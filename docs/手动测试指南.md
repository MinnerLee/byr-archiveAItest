# BYR Archive 手动测试指南

> 目标：**10 分钟内亲手确认这个服务是真的可用**，不依赖任何自动化脚本。
> 所有命令都可以直接复制粘贴到 Git Bash / PowerShell 里执行。
> 手册中的每条命令与期望输出均已实际跑过验证。

---

## 一、30 秒起步（三步）

```bash
# 1. 进入项目目录
cd "D:/BYR Archive"

# 2. 启动服务（默认端口 8080；终端会停在这里，这是正常的）
node src/index.js

# 3. 另开一个终端，确认服务活着
curl -s --noproxy '*' http://127.0.0.1:8080/_health
```

第 3 步应该输出：

```json
{
  "status": "ok",
  "registry": "https://registry.npmjs.org",
  ...
}
```

看到 `"status": "ok"` 就说明服务起来了。

> ⚠️ **必须加 `--noproxy '*'`**。你这台机器配了 HTTP 代理，它会把 `localhost` 的请求也拦走，
> 症状是 curl 报错或返回 000 —— 这不是服务的错。
> 浏览器访问不受影响（浏览器默认对 localhost 直连）。

**停止服务**：在启动服务的那个终端按 `Ctrl + C`。

## 二、用浏览器手动测试（最直观）

服务跑起来之后，**打开浏览器逐个访问下面的地址**，肉眼确认内容：

| # | 地址 | 你应该看到什么 |
|---|---|---|
| 1 | `http://localhost:8080/` | 服务首页，带一张「试试这些地址」的表格，链接可以点 |
| 2 | `http://localhost:8080/vue@3.3.4` | 一大段 JS 代码（Vue 的 UMD 构建），第一行有版权注释 |
| 3 | `http://localhost:8080/vue@3.3.4/` | vue 包根目录的文件列表，`dist/` 目录排在最上面 |
| 4 | `http://localhost:8080/vue@3.3.4/package.json` | JSON 原文，`"name": "vue"` |
| 5 | `http://localhost:8080/react` | React 的入口文件（这条走的是 `exports["."].default` 规则） |
| 6 | `http://localhost:8080/vue@beta/` | 另一个版本的目录列表（dist-tag 解析） |
| 7 | `http://localhost:8080/_stats` | 一大坨 JSON：缓存量、解包信号量、限流状态 |
| 8 | `http://localhost:8080/_metrics` | Prometheus 格式的纯文本指标 |

**进阶：看响应头**。按 F12 打开开发者工具 → Network → 点一个请求 → Response Headers，
应该能看到这些诊断头（这是排查问题的最快方式）：

```
x-byr-entry: dist/vue.global.js (jsdelivr)   ← 入口命中了哪条规则
x-byr-version: 3.3.4                          ← 实际解析到的版本
x-byr-cache: memory                           ← 这次是从哪一层缓存拿的
x-byr-resolution: exact                       ← 版本是怎么解析出来的
```

### 一键浏览器验证（推荐）

项目里有一个现成的演示页，它会**真的用 `<script src>` 引入本服务的包并跑起来**：

```bash
# 先确保服务在 18080 端口跑着
PORT=18080 node src/index.js
```

然后用浏览器打开这个文件（直接双击也行）：

```
D:\BYR Archive\docs\browser-demo.html
```

页面会列出 11 项检查，全部应该是绿色 ✓。重点看这几条：

| 检查项 | 为什么重要 |
|---|---|
| `<script src="/vue@3.3.4">` 加载入口文件 | **这就是 jsDelivr 的核心用法**：浏览器跨域直接引入 |
| 用加载到的 Vue 真实挂载一个组件 | 不只是「变量存在」，是真的渲染出了 DOM |
| 用加载到的 lodash 真实计算 | `_.chunk` 真的算出了结果 |
| 跨域 fetch() 获取 JSON（CORS） | 验证 CORS 头对浏览器真的生效 |
| 动态 import() 加载纯 ESM 包（nanoid） | 验证 `?esm` 逐层重写在浏览器里能跑通 |

页面最后一行应显示 `浏览器端验证：11/11 项通过`。

## 三、用 curl 手动测试（复制粘贴）

下面每条都标注了期望结果，逐条跑即可。

### 3.1 题面要求的四类 URL

```bash
B=http://127.0.0.1:8080

# ① 入口文件（三条入口解析规则各验一条）
curl -s --noproxy '*' -D - -o /dev/null "$B/lodash"      | grep -i x-byr-entry
#   期望: x-byr-entry: lodash.js (main)

curl -s --noproxy '*' -D - -o /dev/null "$B/react"       | grep -i x-byr-entry
#   期望: x-byr-entry: index.js (exports["."].default)

curl -s --noproxy '*' -D - -o /dev/null "$B/vue@3.3.4"   | grep -i x-byr-entry
#   期望: x-byr-entry: dist/vue.global.js (jsdelivr)

# ② 目录列表
curl -s --noproxy '*' "$B/vue@3.3.4/" | head -5
#   期望: <!DOCTYPE HTML> 开头的文件列表

# ③ 直接访问文件
curl -s --noproxy '*' -D - -o /dev/null "$B/vue@3.3.4/package.json" | grep -i content-type
#   期望: content-type: application/json; charset=utf-8

# ④ 不存在的资源 → 404
curl -s --noproxy '*' -o /dev/null -w "%{http_code}\n" "$B/this-pkg-does-not-exist/"
#   期望: 404
```

### 3.2 内容类型（题面强调的 charset）

```bash
for f in package.json README.md dist/vue.runtime.esm-browser.js; do
  printf '%-40s ' "$f"
  curl -s --noproxy '*' -D - -o /dev/null "$B/vue@3.3.4/$f" | grep -i '^content-type' | tr -d '\r'
done
```

期望：

```
package.json                             content-type: application/json; charset=utf-8
README.md                                content-type: text/markdown; charset=utf-8
dist/vue.runtime.esm-browser.js          content-type: application/javascript; charset=utf-8
```

### 3.3 版本解析（可选加分项 1）

```bash
# semver 范围：^3.2.0 应解析到 3.x 里最高的那个版本
curl -s --noproxy '*' -D - -o /dev/null "$B/vue@%5E3.2.0/package.json" | grep -i x-byr-resolution
#   期望: x-byr-resolution: range

# dist-tag
curl -s --noproxy '*' -D - -o /dev/null "$B/vue@beta/package.json" | grep -i x-byr-resolution
#   期望: x-byr-resolution: dist-tag:beta

# 看看范围到底解析到了哪个版本
curl -s --noproxy '*' "$B/vue@%5E3.2.0/package.json" | grep '"version"'
```

### 3.4 缓存（可选加分项 2）

```bash
# 同一个文件请求两次，看 x-byr-cache 变化
curl -s --noproxy '*' -D - -o /dev/null "$B/vue@3.3.4/dist/vue.runtime.esm-browser.js" | grep -i x-byr-cache
#   期望: x-byr-cache: disk    （服务启动后的第一次，从磁盘缓存读）

curl -s --noproxy '*' -D - -o /dev/null "$B/vue@3.3.4/dist/vue.runtime.esm-browser.js" | grep -i x-byr-cache
#   期望: x-byr-cache: memory  （第二次，进了内存 LRU）
```

> ⚠️ 这里的「第一次」是指**服务启动之后**的第一次。
> 如果你之前已经请求过同一个文件（哪怕是在另一个终端里），它已经进了内存 LRU，
> 那么两次都会显示 `memory`。想复现 `disk → memory` 的变化，
> 要么重启服务，要么换一个没请求过的文件。

### 3.5 压缩与打包（可选加分项 3）

```bash
# 服务端即时压缩：体积应该明显变小
curl -s --noproxy '*' -H 'accept-encoding: identity' "$B/lodash@4.17.21/lodash.js" | wc -c
curl -s --noproxy '*' -H 'accept-encoding: identity' "$B/lodash@4.17.21/lodash.js?min" | wc -c
#   期望: 544098 → 约 150000

# 传输压缩：gzip
curl -s --noproxy '*' -H 'accept-encoding: gzip' -D - -o /dev/null "$B/vue@3.3.4/package.json" | grep -i content-encoding
#   期望: content-encoding: gzip

# 打包：把包内相对依赖合并成一个文件
curl -s --noproxy '*' -D - -o /dev/null "$B/mime@3.0.0/index.js?bundle" | grep -i x-byr-bundle
#   期望: x-byr-bundle: inline-cjs

# 深度打包：连外部依赖也内联进来（express 会内联 70 个包）
curl -s --noproxy '*' -D - -o /dev/null "$B/express@4.18.2/lib/express.js?bundle=deep" | grep -i x-byr-bundle
#   期望: x-byr-bundle: deep-inline-cjs
```

### 3.6 HTTP 语义

```bash
# ETag → 304（先拿到 ETag，再带着它请求一次）
ETAG=$(curl -s --noproxy '*' -D - -o /dev/null "$B/vue@3.3.4/package.json" | grep -i '^etag' | sed 's/^[Ee][Tt][Aa][Gg]: //' | tr -d '\r')
curl -s --noproxy '*' -o /dev/null -w "%{http_code}\n" -H "if-none-match: $ETAG" "$B/vue@3.3.4/package.json"
#   期望: 304

# Range → 206
curl -s --noproxy '*' -o /dev/null -w "%{http_code}\n" -H 'range: bytes=0-99' "$B/vue@3.3.4/package.json"
#   期望: 206

# HEAD 请求（只有头没有体）
curl -s --noproxy '*' -I "$B/vue@3.3.4/package.json" | head -3
#   期望: HTTP/1.1 200 OK
```

### 3.7 错误处理

```bash
curl -s --noproxy '*' -o /dev/null -w "%{http_code}\n" "$B/vue@3.3.4/../../../etc/passwd"   # 期望 404
curl -s --noproxy '*' -o /dev/null -w "%{http_code}\n" "$B/-/"                              # 期望 400
curl -s --noproxy '*' -o /dev/null -w "%{http_code}\n" -X PUT "$B/vue@3.3.4/package.json"   # 期望 405
```

## 四、用 CLI 手动测试

项目自带一个命令行工具，同样的能力不用开浏览器就能用：

```bash
# 解析结果概览：版本怎么算出来的、入口命中了哪条规则
node src/index.js info vue@3.3.4

# 完整文件树
node src/index.js tree vue@3.3.4

# 目录列表
node src/index.js ls vue@3.3.4 dist

# 把某个文件吐到本地
node src/index.js cat lodash@4.17.21 lodash.js > lodash.js

# 压缩统计（-s 只打印数字，不输出内容）
node src/index.js min lodash@4.17.21 lodash.js -s

# 打包成单文件
node src/index.js bundle mime@3.0.0 index.js -o bundle.js
node src/index.js bundle express@4.18.2 lib/express.js --deep -o bundle.cjs

# 逐环节自检（★ 最推荐的一条）
node src/index.js verify vue@3.3.4
```

`verify` 会把每个环节都跑一遍并给出结论，期望输出：

```
✓ 包元信息可获取  vue@3.3.4（版本解析方式：exact）
✓ tarball 已下载并解包  38 个文件，共 1.9MB
✓ 入口文件可解析（jsdelivr / exports["."] / main 优先级链）  dist/vue.global.js  ←  命中 jsdelivr
...
vue@3.3.4: 11/11 项通过
```

> 注意：`verify mime@3.0.0` 只有 5/9 项通过 —— **这不是 bug**。
> `mime@3.0.0` 的 package.json 里确实没有 `main` 也没有 `exports`（可以自己解包确认），
> 按题面入口解析规则第 4 条就应该失败。服务会在 404 响应里解释原因。

## 六、常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| curl 报错或返回 `000`，但浏览器能打开 | 本机 HTTP 代理拦截了 localhost | curl 加 `--noproxy '*'` |
| `node src/index.js` 报端口被占用 | 上一个服务进程还在跑 | 换端口：`PORT=8081 node src/index.js`；或 `taskkill //F //IM node.exe` |
| 浏览器打开 `docs/browser-demo.html` 显示 0/11 | 服务没在 18080 端口跑 | 用 `PORT=18080 node src/index.js` 启动（演示页写死了这个端口） |
| 想看「冷启动」的真实耗时 | 缓存里已经有包了 | 删掉缓存：`rm -rf .byr-cache`，再请求一次 |
| 想清空所有缓存重新来 | — | `rm -rf .byr-cache`（缓存目录随时可删，会自动重建） |
| 私有源怎么测 | 需要一个真的私有 registry | 设 `REGISTRY=https://你的私有源` 再启动；`.npmrc` 里的配置也会被读取 |
| Windows 下杀不掉服务进程 | — | `taskkill //F //IM node.exe`（注意 Git Bash 里是两个斜杠） |

## 七、测什么算「通过」

| 类别 | 通过标准 |
|---|---|
| 入口解析 | `/vue@3.3.4` 命中 jsdelivr、`/react` 命中 exports、`/lodash` 命中 main；三者 Content-Type 均为 `application/javascript; charset=utf-8` |
| 目录列表 | HTML、列出 `package.json` 与 `README.md`、子目录排在文件前面 |
| 版本解析 | `^3.2.0` 解析到 3.x 最高版、`beta` 解析到预发布版、`x-byr-resolution` 头如实标注方式 |
| 缓存 | 第二次请求 `x-byr-cache: memory`，且耗时明显低于第一次 |
| 压缩 | `?min` 后体积下降且语法仍合法；gzip 后体积再降 |
| 打包 | `?bundle` 产物自包含；`?bundle=deep` 产物在 Node 里能 `require` 并真正运行 |
| 错误处理 | 不存在的资源 404、非法输入 400、错误方法 405，**全程无 5xx** |
| 浏览器 | `docs/browser-demo.html` 11/11 项通过，无控制台报错 |
